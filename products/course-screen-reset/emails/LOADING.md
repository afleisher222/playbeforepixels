# Loading the 30 Days of Back-and-Forth emails

Every email is finished text. Nothing needs the founder: no notes to write, no boxes to fill. Loading is a one-time account-setup job that a Claude Code routine can do once the account exists (ops/PAUSE stays until then). Platform feature names below are from memory and UNVERIFIED; check them on the platform on setup day.

All files are generated by `build/emails.js` from `build/content.js`. After any text change, run `sh build/make.sh --final` and reload the changed emails.

## What is here

| Folder | What | Count |
|---|---|---|
| `emails/*.html` + `emails/*.md` | Paid program for an email platform (HTML is email-safe, 600 px, inline styles) | 35 |

The paid program is 35 emails: the welcome and access email (day 0, with the workbook link and the guarantee), 30 daily lessons, check-ins on days 3, 10 and 30, and the day-31 wrap-up.

## Option A: Gumroad only (simplest; matches ops/QUEUE.md "Gumroad from Dec 15")
1. Product: "30 Days of Back-and-Forth", $27. Attach the five files in `downloads/` (START HERE first). Gumroad's receipt delivers them, and buyers can download again from their Gumroad Library.
2. Create a workflow for this product (and one for the $49 bundle, with the same emails). For each file in `emails/gumroad/`, in order, add one email with the delay in `workflow.json` (0 = right after purchase). Paste the subject and the Markdown body.
3. Replace `{{business_mailing_address}}` in every file first, with the public mailing address in legal/ENTITY.md (the USPS PO Box). One command does it: `sed -i 's/{{business_mailing_address}}/<the PO Box>/' emails/gumroad/*.md funnel/gumroad/*.md` (do not commit the result if the address is not yet public).
4. Free starter: a $0 Gumroad product with the two PDFs in `funnel/starter/`, plus a workflow built from `funnel/gumroad/` in the same way.
5. Gumroad adds its own unsubscribe footer, so this edition has no unsubscribe or pause link. It sends each email a set number of days after purchase, not at a set local time, so the copy says "each day", never "each morning".
6. Links that must exist on the site before launch (the site workflow builds them): `/30-days` (sales page with `#bundle`), `/30-days/start`, `/30-days/feedback` (a one-question form: "Which play or page did your child go back to?"), `/shipping-returns/`, `/help`, `/bonus/course-screen-reset`.
7. Gumroad cannot stop the free sequence when someone buys (UNVERIFIED). A buyer may still get free emails 6 and 7, which only invite them to the program; that is acceptable.

## Option B: an email platform (Kit, MailerLite or similar) with Gumroad as the checkout
1. Import `emails/*.html` in the order of `emails/sequence.json` (day N at 7:00 in the subscriber's time zone; check-ins at 16:00). Import `funnel/*.html` as the free sequence and stop it on purchase.
2. Trigger the paid sequence with the tag `30days-buyer`, added by the checkout integration (Gumroad to the platform, usually through the platform's own Gumroad integration or a webhook: UNVERIFIED).
3. Map the merge tags listed in `sequence.json`. `{{business_mailing_address}}` is normally the platform's account address setting. Upload `brand/logo/png/lockup-horizontal-2400.png` once for `{{logo_url}}`.
4. This edition includes a "Pause or change the send time" link. Keep it only if the platform supports it; otherwise delete that line from the footer in `build/emails.js` (`frame` and `mdFoot`) and rebuild.

## Before switching on
- Send the full sequence to a test inbox and click every link.
- Refund wording in every email matches legal/SHIPPING-RETURNS-REFUNDS.md Part B §4 (14 days, no more than 30% of lessons; after that no refund, but the buyer keeps the emails and workbook) and §3 (broken files fixed or refunded). The numbers come from `REFUND` in `build/content.js`.
- No email promises a reward for sharing; there is no referral program.
